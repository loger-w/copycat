## 下一件事:三個既有 bug(全在 `docs/next-time.md` 2026-07-30 段)

### 1. P1 `futures_engine` 間歇性整段零推播 — 先求穩定重現,不要直接動 fallback

**兩個相反的實測狀態**:

- (i) 2026-07-29 17:33 起跑的 server 到 00:50 為止 TXF/MXF/TMF 全 `p=null`、`seq=0`
  (期貨面板整晚無資料),而**同時段獨立訂閱 `TC.F.TWF.TXF.HOT` 有 235 則/30 秒、
  MXF 324 則、五檔俱全** → TC4 端正常,問題在 server 內。
- (ii) 2026-07-30 10:24 起跑的 server 六腿含 TXF 全部正常有值。

**已知機制**:TXO runtime 的訂閱清單含 `SPOT_SYMBOL = "TC.F.TWF.TXF.HOT"`
(`copycat/server/engine.py:89`),`futures_engine` 訂同一 symbol 時 TC4 只推一邊
(CLAUDE.md §8);`futures_engine` 的 leaf fallback 需先「由推播解析出契約月份」才會補訂
leaf,全零推播時啟動不了。

**觸發條件未定位** —— 疑似與啟動時序 / TC4 session 殘留(前一個 server 被 kill 未正常
Disconnect)/ 先前有 process 訂過同 symbol 有關。走 `/bug`,Phase 1 的重點是**穩定重現**
(鐵則 A),重現不了就不要改 code。

**修法候選**(重現後再選):leaf fallback 改為可由非推播來源取得月份(合約清單查詢);
或 runtime 與 futures_engine 共用單一 TXF 訂閱。

**連帶影響**:`corr_engine` 的 base 腿(台指)讀 `futures_engine.state()` 取五檔算中價,
上游空著時五對相關係數全部回 `None`(引擎行為正確、有測試覆蓋,但畫面沒數字)。

### 2. P1 `test_index_engine::test_rollover_two_phase` 只在真實時鐘 ≥ 08:30 才綠

`_rollover_loop`(`copycat/server/index_engine.py:279`)以 `_dt.datetime.now().time()` 判
08:30 門檻,**該時鐘沒有注入點** —— 同一個建構子已經注入了 `today_fn` 與
`in_watch_window`,唯獨漏了它。

決定性實驗(已做):把模組的 `_dt` 換成固定 10:00 的 shim → 立即轉綠;00:2x 跑 5/5 紅、
09:5x 跑 6/6 綠。**修法:建構子補 `now_fn: Callable[[], _dt.time]` 注入**,測試傳固定值。

### 3. P2 兩條測試依賴未進版控的 `spikes/TCPY/`

`test_tc4.py::TestConnectInterruptible` 與 `test_tc4_trade.py::TestFailedConnectGcSafety`
會 import TC4 官方 wrapper,而 `spikes/TCPY/` 被 `.gitignore:9` 排除 → **任何乾淨 checkout
